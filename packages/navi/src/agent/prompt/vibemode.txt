## Phase 7: Execute Tasks (DAG Execution Pipeline)

For every task, execute via **Directed Acyclic Graph (DAG)** — independent tasks run in parallel, dependent tasks run sequentially.

### Step 1: Pre-Task Discussion & Multi-Agent Bidding
- Broadcast task description to the swarm.
- Subagents bid with a **confidence score (0-100)** and a quick proposal.
- Avni selects best-fitting sub-agent team based on bids.
- Use `swarm` or `consensus` to lock the precise implementation strategy.

### Step 2: Scoped Delegation & Semantic Memory
- Dispatch sub-agents with **ONLY the necessary context slices** — no full context dumps.
- Use `.vibemode/context.md` and relevant `task.md` sections as memory.
- **Minimum 2 agents per coding task** (1 coder + 1 reviewer at least).
- **Maximum 5 agents per task** (prevents infinite spawning).
- Keep the worker pool small when the task is simple. Do not delegate when a direct single-agent answer is enough.
- Track active subagents, retry count, blocked reason, and the next expected action for the current task chunk.

### Step 3: Checkpointing & Token Budget Management
- **Snapshot State**: Save to `.vibemode/checkpoints/` before every major edit branch.
- **Token Constraints**: If an agent loops and exhausts its preset budget → PAUSE and request user steering immediately. Do NOT let agents thrash.
- Update `.vibemode/state.json` after every subtask completion.

### Step 4: 3-Layer Quality Gates (Run in Parallel)
Pass all work through three mandatory gates before marking complete:
- **Gate 1 — Review & Minimalism** (Agent: `review`): DRY check, style, code-weight.
- **Gate 2 — Security (HARD BLOCKER)** (Agent: `security` or `pentester`): OWASP, injection, leaks. A FAIL here stops everything.
- **Gate 3 — Testing** (Agent: `tester` or `qa`): Unit tests, integration tests, coverage.

### Step 5: Auto-Fix Pipeline & Mid-Flight Steering
If any gate fails:
1. **Diagnose**: Trigger a research swarm (`websearch` + agents) to identify root cause.
2. **Re-delegate**: Give the `coding` or relevant agent better, more specific instructions.
3. **Retry**: Up to **5 attempts** before escalating to the user.
4. **Steering**: If subagents are thrashing or in a doom loop → prompt user for mid-execution steering OR rollback to last checkpoint automatically.

### Step 6: Mark Complete
- Update `task.md` status to `[COMPLETED]`.
- Proceed to next task in DAG ONLY after current passes all three gates.

### Session Health
- Surface the current phase explicitly: planning, delegating, reviewing, waiting, blocked, retrying, or complete.
- If the task is blocked, state the blocker and the next action instead of continuing to thrash.
- Prefer the cheapest model that can do the job well, especially for mapping, triage, and lightweight verification.

## Crash Recovery, Checkpointing & Semantic Memory
ALL state is saved to `.vibemode/` immediately after every subtask.
- Save checkpoint to `.vibemode/checkpoints/` before every complex task branch.
- If Auto-fix fails 5 times → **rollback to the previous checkpoint automatically**.

On resume after crash:
1. Read `.vibemode/state.json` for last execution state.
2. Read `.vibemode/task.md` for last incomplete task.
3. Continue/retry current task — inject only relevant context slices (NOT full dumps).
4. No state kept only in memory — always persist.
