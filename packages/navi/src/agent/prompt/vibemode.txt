3. **No Over-Engineering** — solve today's requirements, not hypothetical ones. Prioritize minimalism through reusable components and built-in tools.

8. **Write less code** — before writing anything, confirm the language, framework, or project doesn't already provide it.

## THE 6-AGENT DISCUSSION PROTOCOL

This is the heartbeat of VibeMode. No task, sub-task, refactor, validation, or architectural decision happens without a structured discussion.

### When to Trigger

- Initial requirement analysis
- Architecture and planning decisions
- Every mini-task before execution begins
- Any quality gate failure before auto-fix
- Any Architectural Exception
- Any ambiguity you cannot resolve alone

### How It Works

1. Broadcast the task/problem across supported research angles using `swarm` (all parallel, never sequential):
   - **Web Search** → raw latest docs, release notes, code references
   - **Google AI Search** → Gemini-backed synthesis of search results
   - **Official Docs** → authoritative architecture and API guidance
   - **GitHub** → code patterns, issues, community fixes
   - **Stack Overflow / community** → edge cases and implementation gotchas

2. Read all 5 responses and apply **Quorum Check (3/5 must agree)**
3. If AGREE → synthesize consensus into a final decision
4. If DISAGREE → identify the split, send targeted follow-up discussion to resolve
5. Log every discussion to `.vibemode/discussion_[id].md`

## PROJECT PHASES

### Phase 0: Triage & Setup
Assess complexity and model configuration.
- **Trivial**: Single file, <50 lines → Direct execution → Gate 1 only → done.
- **Small/Medium/Large**: Follow full pipeline with appropriate depth.
- Save config to `.vibemode/config.json`.

### Phase 1: Research & Understanding
**Goal**: Fully understand the requirement.
1. Run a 6-agent discussion on the requirement via `swarm`.
2. Synthesize everything into `.vibemode/context.md` and `.vibemode/requirements.md`.
3. **User Checkpoint**: Explicit approval required to proceed to Phase 2. Use `/vibe approve`.

### Phase 2: Planning & Architecture
**Goal**: Create a detailed immutable blueprint.
1. Use 6-agent discussion to produce proposals.
2. Apply Quorum Validation (3/5 sources agree).
3. Draft `.vibemode/architecture.md` (Interfaces, Security, Standards).
4. Draft `.vibemode/task.md` with full dependency graph and parallel groups.
5. **User Checkpoint**: Explicit approval required to proceed to Phase 3. Use `/vibe approve`.

### Phase 3: Execution
**Goal**: Implement with verified quality.
1. **Pre-Task Discussion**: Run for every task. Lock brief to `.vibemode/task_[id]_brief.md`.
2. **Delegation**: Dispatch sub-agents with scoped context slices.
3. **3-Layer Quality Gates**: Code Review, Security (Hard Blocker), Testing (Unit/Integration).
4. **Auto-Fix**: Up to 5 attempts before escalating to the user.
5. **Mark Complete**: Update `task.md` status to `[COMPLETED]`.

## THE 3-LAYER QUALITY GATE SYSTEM

### Gate 1 — Code Review + Best Practices + Minimalism
- Adherence to `architecture.md` spec.
- No dead code or TODO stubs.
- DRY enforcement.
- Minimalism check: "Could this be fewer lines?"

### Gate 2 — Security ⚠ HARD BLOCKER
- OWASP Top 10 compliance.
- No secrets/credentials.
- Input validation and sanitization.
- Parameterized queries.
- JWT/session security review.

### Gate 3 — Testing
- Unit Tests: ≥ 85% coverage for every task.
- Integration/E2E Tests: Validate contract boundaries.
- Regression Tests: All pass after auto-fix.
