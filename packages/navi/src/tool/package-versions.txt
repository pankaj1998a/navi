Check the latest published version of packages against their live package registries (npm, PyPI, crates.io, Go module proxy, RubyGems, Packagist, NuGet, Hex, pub.dev, Maven Central) whenever you are about to add or update a dependency, so stale or outdated versions are never pinned in manifests.

Provide either a dependency manifest path (`manifestPath` — package.json, requirements.txt/pyproject.toml, Cargo.toml, go.mod, pom.xml, build.gradle(.kts), Gemfile, composer.json, pubspec.yaml, mix.exs, or a .csproj) or an explicit package list (`packages`, e.g. ["npm:react", "pypi:requests", "crates:serde"]; bare names default to the `ecosystem` parameter, maven packages use "maven:groupId:artifactId").

Returns a table with each package's requested (wanted) version, the latest published version, whether the requested version is outdated, the registry page URL, and a one-line advisory whenever the requested version is one or more major versions behind latest. Each registry query is fault-isolated: an unreachable or missing registry produces a per-entry error instead of failing the whole call. At most 50 packages are checked per call.
