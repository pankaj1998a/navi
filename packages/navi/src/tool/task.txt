Launch a new agent to handle complex, multistep tasks autonomously.

When using the Task tool, you must specify a subagent_type parameter to select which agent type to use.

When to use the Task tool:
- When you need specialized autonomous investigation, exploration, debugging, security auditing, or optimization.
- When you are instructed to execute custom slash commands. Use the Task tool with the slash command invocation as the entire prompt.
- To run parallel subtasks concurrently (e.g. exploring multiple components or running security and review checks).

When NOT to use the Task tool:
- If you want to read a specific file path, use the Read or Glob tool instead of the Task tool, to find the match more quickly.
- If you are searching for a specific class definition like "class Foo", use the Glob tool instead.
- If you are searching for code within a specific file or set of 2-3 files, use the Read tool instead.
- Simple single-action tasks that can be answered immediately.

Available Subagents:
- "explore": Fast codebase search and navigation (glob, grep, read, webfetch). Read-only.
- "debugger": Root-cause isolation, stack trace dissection, bug diagnosis, and minimal reproduction test generation.
- "security": Vulnerability auditor (OWASP Top 10, secret detection, injection, auth bypasses, dependency flaws). Read-only.
- "optimizer": Runtime profiling, time/memory complexity reduction, and dead code refactoring.
- "reviewer": Elite code quality and conventions auditor. Inspects diffs and catches subtle edge cases. Read-only.
- "architect": High-level system design, decomposition, and roadmap planning.
- "tdd": Test-Driven Development specialist. Writes tests first and follows red-green-refactor cycles.
- "researcher": Deep evidence-backed research across web sources and external docs.
- "general": General-purpose multi-step autonomous agent.

Usage notes:
1. Launch multiple agents concurrently whenever possible, to maximize performance (use a single message with multiple Task calls).
2. If any subagent encounters a data error (such as invalid JSON, unparseable response, schema mismatch), the main agent is notified immediately and running sibling tasks can fail-fast to save tokens and time.
3. You can supply `timeout_seconds` to bound long operations, `max_steps` to limit iterations, `isolate: true` for safe sandboxed execution, and `format: "json"` for programmatic machine parsing.
4. When the agent is done, it returns a concise summary including duration, tools invoked, files touched, and task_id.
5. To resume or follow up on a previous subagent run without starting over, pass the `task_id`.
